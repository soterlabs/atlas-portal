# Search artifacts: what they are and how to keep them fresh

The Atlas search runs entirely in the browser (and, for phones, on one server route)
from five prebuilt artifacts in `public/`. Each one is pinned to the SHA-256 of the
parsed Atlas tree it was built from. When the deployed Atlas moves, every artifact goes
**stale** and the engine degrades silently:

| Artifact                          | When stale                                                                    |
| --------------------------------- | ----------------------------------------------------------------------------- |
| `atlas-search-index.json`         | the index rebuilds in the browser on every page load, without expansions      |
| `atlas-search-vectors.{json,bin}` | semantic ("Similar") results turn off                                         |
| `atlas-search-families.json`      | duplicate collapsing turns off                                                |
| `atlas-abbreviations.json`        | acronym expansion turns off                                                   |
| `atlas-graph.json`                | Related section, suggestion chips and definition answers turn off (see below) |

## The rule: refresh before every deploy, check in CI

```bash
npm run search:refresh-artifacts     # composes the current Atlas from GitHub, rebuilds all, verifies
npm run search:check-artifacts       # exit 1 with both hashes named when anything is stale
```

Run the refresh as the last step before a deploy and commit its output. The Atlas
changes every few days, so this is a standing operation, not a one-time step. The
`search-artifacts` job in `.github/workflows/ci.yml` runs the check so a stale deploy
fails loudly instead of shipping degraded.

Without an argument the checker, and therefore the CI job, compares the artifacts with
`https://sky-atlas.io/api/atlas.json`. If that is not your production deployment, pass
your own `/api/atlas.json` URL (or a JSON path): `npm run search:check-artifacts -- <url>`.

`GITHUB_TOKEN` (in `.env.local`) is optional but raises the GitHub rate limit for the
compose step. The vector build downloads the embedding model from huggingface.co on
first run (about 35 MB, cached under `.cache/transformers/`, override with
`TRANSFORMERS_CACHE_DIR`). No OpenAI or Anthropic key is needed.

## Individual builders

Each takes the corpus URL or a JSON path; `search:refresh-artifacts` runs them all
against one snapshot so the hashes always agree.

- `npm run search:build-index -- <corpus>`
- `npm run search:build-vectors -- <corpus>`
- `npm run search:build-families -- <corpus>` (reads `data/duplicate-census.json`, produced by
  `npx tsx scripts/duplicate-census.ts <corpus> --out data/duplicate-census.json --cosine`)
- `npm run search:build-abbreviations -- <corpus>` (applies `data/abbreviation-curation.json`)
- `npm run search:build-graph-artifact -- <corpus>` (needs `data/graphrag/`, see below)

## The graph is not part of this drop

`data/graphrag/` data files and `public/atlas-graph.json` are omitted on purpose: the
knowledge-graph data is regenerated by a separate pipeline and was not current at
handoff. The checker reports the graph as `omitted` (not a failure) while the data
directory is absent. When the data arrives, drop it into `data/graphrag/` (contract:
`data/graphrag/schema.md`), run `npm run search:build-graph-artifact`, and the Related
section, suggestion chips and definition answers switch on with no code change.

## Expansions (optional, paid)

`data/search/expansions.json` carries AI-written paraphrases that the index folds in.
The refresh never regenerates them. Documents added since the last run simply lack
paraphrases (search still finds them). To top up, set `OPENAI_API_KEY` or
`ANTHROPIC_API_KEY` in `.env.local` and run `npm run search:generate-expansions`.

## Configuration knobs (build time)

`NEXT_PUBLIC_SEARCH_MODE` (`auto` default, `local`, `low-memory`) is inlined at build
time. Phones and low-memory devices use the server route `/api/search/dense`, which
needs outbound access to huggingface.co on cold start (or a self-hosted model path).
Artifact loading needs a secure context (WebCrypto): serve over HTTPS only.
